# 关机后仍可创作

现有 GitHub 网址只是入口；关机可用需要持续运行的云后台。本项目已提供 Linux Docker 部署文件，保留现有可灵 v3、Kokoro 中文配音、FFmpeg 字幕与视频合成流程。云端使用 CPU 配音，无需购买 GPU。

## 最少操作：连接 GitHub 部署

准备入口：[云端部署与费用说明](https://719566486.github.io/yingke-aigc-studio/cloud.html)。本次按用户选择仅准备，不创建收费服务。

费用预算（2026-11-01查询官方价格）：2核4GB服务按每月75–85美元预留，10GB磁盘按0.25美元/GB/月约2.50美元，基础合计约77.50–87.50美元/月，因此建议预留80–90美元/月。公开价格页检索快照存在差异，实际以创建界面的报价为准；可灵调用、超额流量、税费、可选工作区计划另计。来源：https://render.com/pricing 。不需要单独购买GPU；默认单队列。

扫码交付：成片完成后页面显示二维码；手机无须原电脑Cookie，扫码到领取页保存MP4。随机领取链接最多24小时有效，且不超过作品剩余保存期；默认作品在创建后72小时清理。持有二维码的人均可取片，勿公开张贴私人作品。视频、领取数据库与会话数据库均在/app/data持久磁盘，云部署后的二维码使用云域名，电脑关机不影响。临时本机分享二维码不具备此保证；迁移前生成的旧码不会自动改成新云码，需云端重新生成。

1. 打开 [Render 部署入口](https://render.com/deploy?repo=https://github.com/719566486/yingke-aigc-studio)，登录并连接现有 GitHub 仓库。
2. 页面会读取 render.yaml：新加坡、2 核 4GB、10GB 持久磁盘。它是收费配置，先查看平台显示的总费用，再由你确认创建。可灵生成费用另计；本地电脑的程序不会自动购买服务器。
3. 在平台的密钥设置填写 STUDIO_KLING_API_KEY。地址沿用当前北京区；如账户需要其他区，修改 STUDIO_KLING_BASE。STUDIO_MASTER_KEY 由平台自动生成，保留原值，不要随意更换。不要把密钥放入 GitHub。
4. 服务部署成功后，复制分配的 HTTPS 网址到本机，运行下述“切换入口”工具。访客无需输入体验码；主密钥和可灵 Key 不用于分享。
5. 完成云端免费预演核验并切换原 GitHub 入口后，关闭本机分享，关机，再用手机流量检查一次。原电脑不必继续运行。

云端部署并不会迁移旧成片、旧浏览器会话或本机配置。原作品继续保存在这台电脑。云端访客各自会话隔离；全站滚动24小时10个AI任务，单浏览器会话1个AI任务。用户仍需确认使用活动生成额度。

## 切换入口

在本机项目目录运行：

    .\.venv\Scripts\python.exe -B deploy\activate_cloud.py

工具会在本机提示填写云端网址，不要求输入可灵 Key 或云端主密钥。先检查公网连通、访客权限和真实云端免费预演，全部通过后自动更新固定入口并同步 GitHub；完成后停止本机对外分享。正式云后台尚未核验时，原入口继续使用本机分享连接。

## 已有云服务器

建议起点：Linux x86_64、2核4GB、至少20GB可用磁盘，可访问可灵接口及模型下载源，已安装 Docker Compose。实际活动并发需要另测；当前仍按单队列逐个处理。

将源码放到云服务器，创建服务器私有的 data/cloud.env：

    STUDIO_MASTER_KEY=<32字节base64加密密钥>
    STUDIO_KLING_API_KEY=<你自己的可灵API密钥>
    STUDIO_KLING_BASE=https://api-beijing.klingai.com/v1
    STUDIO_PUBLIC_HOSTS=<你的域名，不含https://和斜杠>
    STUDIO_SHARE_DAILY_LIMIT=10

在服务器用 cryptography.fernet.Fernet.generate_key() 生成主密钥；设置文件权限仅管理员可读。不要复制 Windows 的加密 settings.json 到 Linux。

将域名指向服务器，开放80/443端口，运行 docker compose up -d --build。Caddy 自动申请 HTTPS，管理员8787端口不对外开放。持久卷保存数据库与作品，容器意外退出后自动重启。仅运行一个 studio 实例，不能简单增加 worker 数量。备份持久卷与主密钥；不要执行删除卷的命令。

## 当前验收边界

本机测试、GitHub Linux 容器检查、真实云平台运行是三个不同环节。以各自实际报告为准；上传了 Dockerfile 或通过 CI 都不代表已开通长期服务器。切换入口前必须有已部署的真实云端 HTTPS 地址。

配置依据：[Render Blueprint](https://render.com/docs/blueprint-spec)、[持久磁盘](https://render.com/docs/disks)、[Docker Compose](https://docs.docker.com/reference/compose-file/services/)、[Kokoro 中文模型](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)。
